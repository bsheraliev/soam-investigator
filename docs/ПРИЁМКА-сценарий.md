# Сценарий приёмки SOAM Investigator — для отдела расследований

Версия сценария: 2 (2026-10-11), под приложение v0.5.1 (добавлены шаги 11 — PIRATe и 12 — сервер).
Адрес: https://bsheraliev.github.io/soam-investigator/ — открыть в Chrome или Edge на компьютере. Все данные остаются в браузере, на сервер ничего не уходит.

Цель приёмки: пройти одно расследование от регистрации до отчёта и отметить, где приложение ведёт не так, как привыкли работать по SOAM, или где непонятно.

## Как записывать замечания
В конце — таблица. На каждое замечание: номер шага, что ожидали, что увидели, насколько мешает (мешает работать / неудобно / пожелание).

## Шаг 0. Знакомство (5 минут)
1. Меню «О методологии»: прочитать процесс, раскрыть «Глоссарий QRG».
2. Меню «Тестовые кейсы» → «Загрузить» кейс «Гамильтон 2015» → открыть дело → вкладка «Схема». Сверить с QRG стр. 49: блоки и связи должны совпадать.

Ожидаемый результат: схема читается, цвета элементов понятны (барьеры, участие человека, контекстные условия, OSF, исход).

## Шаг 1. Новое дело
Меню «Дела» → «Новое дело». Заполнить название, дату, место; тип «Инцидент»; тяжесть (попробовать A, затем E — подсказка под «Решение о расследовании» должна поменяться); решение «Расследовать по SOAM»; исход — по одному пункту на строку. «Создать».

Ожидаемый результат: открывается вкладка «Факты»; в шапке дела — название, тип, тяжесть, статус «Черновик».

## Шаг 2. Факты (SHEL/O)
Добавить 5–8 фактов из любого реального или учебного события. У каждого: текст, элемент SHEL/O (подсказки появляются при выборе элемента), источник; к одному факту прикрепить файл (до 5 МБ). У одного факта поставить «нужны дополнительные данные» и записать вопрос.

Ожидаемый результат: факты в таблице, вложение открывается по ссылке, статус дела стал «Сбор данных».

Проверить: подсказки SHEL/O соответствуют QRG стр. 12–15.

## Шаг 3. Хронология
Добавить 3–4 события с временем, к каждому привязать факты галочками. Одно событие — без времени.

Ожидаемый результат: события по времени, без времени — в конце.

## Шаг 4. Сортировка (тест вклада и классификация)
Для каждого факта ответить на тест вклада «да / нет». Для «да» — кнопки HI / CC / OSF / BAR: выбрать элемент, заполнить подкатегорию, прочитать контрольный вопрос и поставить галочку подтверждения, «Сохранить». Попробовать сохранить без галочки — должно не дать. Хотя бы один барьер пометить «отказал», один — «сработал». Над списком раскрыть подсказку «Element Review Chart».

Ожидаемый результат: у фактов появляются метки элементов; статус дела «Анализ»; факты с «нет» видны в отчёте как «Прочие вопросы безопасности».

Проверить: контрольные вопросы 1–4 совпадают с QRG стр. 20–42; формулировка участия человека без оценочных слов (Just Culture).

## Шаг 5. Схема
Вкладка «Схема»: «Предложить связи» (по фактам одного события хронологии), затем добавить связь вручную — клик по блоку, клик по второму. Экспорт SVG и PNG.

Ожидаемый результат: схема как в QRG (4 колонки + исход), сработавший барьер — другим цветом, файлы скачиваются.

## Шаг 6. Меры
Добавить меры так, чтобы закрыть все OSF и отказавшие/отсутствующие барьеры. Попробовать сохранить меру без «адресует» и без ответственного — должно не дать. Отметить SMARTER.

Ожидаемый результат: сводка «Покрытие» зелёная; статус дела «Меры». Меню «Реестр мер» показывает меры со сроками.

## Шаг 7. QA и завершение
Вкладка «QA»: кнопка «Завершить» неактивна, пока есть незакрытые пункты. Закрыть открытый вопрос из шага 2, записать ключевые уроки, отметить 12 пунктов. Нажать «Завершить».

Ожидаемый результат: статус «Завершено», дата завершения в шапке.

## Шаг 8. Отчёт
Вкладка «Отчёт»: «Печать / сохранить в PDF». Проверить состав разделов: исход, факты, хронология, схема, факторы по элементам с доказательствами, меры, прочие вопросы, уроки, QA.

Ожидаемый результат: без плашки «ЧЕРНОВИК»; PDF читается.

## Шаг 9. Экспорт и импорт
Вкладка «Событие» → «Экспорт в JSON». На главной — «Импорт», выбрать файл. Согласиться на замену.

Ожидаемый результат: дело восстановлено целиком, включая вложения, связи и меры.

## Шаг 10. Офлайн
Отключить сеть (режим «в самолёте»), перезагрузить страницу, открыть дело.

Ожидаемый результат: приложение открывается и работает без сети.

## Шаг 11. Режим PIRATe (проактивная оценка)
На главной — «Проактивная оценка (PIRATe)». Выбрать повод (например, «повторяющиеся события»), записать группу экспертов, описать сценарий «наше следующее происшествие», создать. Пройти факты → сортировку → схему → меры как в шагах 2–6 (хронологию можно пропустить).

Ожидаемый результат: тяжесть и решение о расследовании не запрашиваются; в шапке метка PIRATe; отчёт подписан «Проактивная оценка рисков по методике PIRATe» со строками «Повод» и «Группа экспертов». Правило «каждый барьер и OSF закрыт мерой» действует.

## Шаг 12. Сервер организации (если развёрнут)
Меню «Сервер»: войти по адресу, почте и паролю, выданным администратором. На вкладке «Событие» любого дела — «Отправить на сервер». На главной — карточка «Дела организации на сервере», у другого пользователя — «Получить». На странице «Реестр мер» — переключатель «На сервере».

Ожидаемый результат: дело появляется у коллеги с той же версией; при одновременной правке второй получает предупреждение о версии; без входа приложение ничего не отправляет.
