# SOAM Investigator — руководство пользователя

Версия 1 (2026-10-11), под приложение v0.5.16. Адрес: https://bsheraliev.github.io/soam-investigator/ (Chrome или Edge). Приложение работает без сети; все данные хранятся в вашем браузере, пока вы сами не отправите дело на сервер организации.

## 1. Главная — «Дела»
- Список дел: название, дата, тип, тяжесть, статус. Строка открывает дело. Поиск по названию и месту.
- «Новое дело» — расследование события по SOAM. «Проактивная оценка (PIRATe)» — гипотетический сценарий «наше следующее происшествие» тем же процессом.
- «Тестовые кейсы» — три опубликованных в QRG примера (BAC 1-11 1990, Бангкок 1999, Гамильтон 2015) для обучения и сверки схемы.
- «Импорт дела из JSON» — загрузить файл одного дела или копию всех дел. «Скачать все дела (копия)» — резервная копия всех дел браузера одним файлом с вложениями. Напоминание появляется, если копия не делалась больше недели.
- Если выполнен вход на сервер организации — карточка «Дела организации на сервере» с кнопкой «Получить».

## 2. Дело — вкладка «Событие»
- Название, дата, место; тип (авиационное происшествие или инцидент); тяжесть A–E по схеме EUROCONTROL (для АП не требуется); решение о расследовании с рекомендацией методологии; исход события (по пункту на строку).
- Статус дела продвигается сам: факт → «Сбор данных», классификация → «Анализ», мера → «Меры». Назад — вручную здесь же (только на соседний статус).
- «Экспорт в JSON» — файл одного дела с вложениями. При входе на сервер — «Отправить на сервер» и отметка версии на сервере.
- В режиме PIRATe вместо тяжести и решения — «Повод» и «Группа экспертов», поле «Сценарий: что может произойти».

## 3. «Факты» (SHEL/O)
- Факт: текст, элемент SHEL/O (S — процедуры и документация, H — оборудование, E — среда, L — люди, O — организация), источник, вложения до 5 МБ каждое.
- Подсказки по элементу SHEL/O — из QRG (стр. 12–15). Флаг «нужны дополнительные данные» с вопросом — открытый вопрос; дело не завершится, пока он не закрыт на вкладке QA.
- Сбор данных и анализ — повторяющийся цикл: пробелы, найденные при сортировке, записывайте как открытые вопросы и возвращайтесь к сбору.

## 4. «Хронология»
- События с временем и описанием; к каждому можно привязать факты галочками. События без времени показываются в конце.
- Привязка нужна для «Предложить связи» на схеме: факты одного события связываются между соседними уровнями.

## 5. «Сортировка» — тест вклада и классификация
- Для каждого факта ответьте на тест вклада: «да» — факт идёт в анализ; «нет» — в раздел «Прочие вопросы безопасности» отчёта.
- После «да» — кнопки HI / CC / OSF / BAR. Для каждого элемента показывается контрольный вопрос из QRG; сохранить классификацию можно только с галочкой подтверждения. Один факт может иметь несколько классификаций.
- HI (участие человека) формулируется как действие или бездействие, без оценок (Just Culture). CC — категория контекстных условий; OSF — один или несколько из 12 кодов; BAR — тип барьера и состояние: отсутствовал, отказал, сработал.
- Подсказки: «Как отличить элементы» (SOAM Element Review Chart) и «Safety-II: что сработало правильно». «Следующий неотсортированный» ведёт по списку.

## 6. «Схема» (SOAM Chart)
- Четыре колонки (барьеры, участие человека, контекстные условия, организационные факторы) и исход, как в QRG. Сработавшие барьеры — отдельным цветом.
- Связь: нажмите узел, затем узел соседней колонки; повтор по той же паре убирает связь. Барьер → исход ставится автоматически при классификации. «Предложить связи» — по фактам одного события хронологии. Подсказка «Когда проводить связь» — из QRG стр. 46.
- Экспорт SVG и PNG. Узлы доступны с клавиатуры (Tab, Enter).

## 7. «Меры»
- Правило SOAM: каждый отсутствующий или отказавший барьер и каждый OSF должен быть закрыт хотя бы одной мерой. Сводка «Покрытие» показывает, что ещё не закрыто.
- Мера: текст, что адресует (барьеры и OSF, не люди), ответственное подразделение, срок, статус, отметки SMARTER, чек-лист мер из QRG.

## 8. «QA» и завершение
- 12 пунктов контрольного списка качества с заметками; открытые вопросы по фактам с кнопкой «Закрыть»; ключевые уроки и кому доведено.
- «Завершить» доступна, когда сводка готовности зелёная: неотсортированных 0, неподтверждённых 0, открытых вопросов 0, покрытие 100 %, уроки записаны, QA 12 из 12. При входе на сервер завершённое дело отправляется туда автоматически.

## 9. «Отчёт»
- Печатная форма: реквизиты, исход, факты, хронология, схема, факторы с доказательствами (источник и вложения), меры, прочие вопросы, открытые вопросы, уроки, QA. До прохождения QA — плашка «ЧЕРНОВИК».
- «Печать / сохранить в PDF» и «Скачать Word (DOCX)» (схема картинкой, колонтитул с номерами страниц).

## 10. «Реестр мер»
- Все меры по делам этого браузера или, при входе, по всем делам организации с сервера: просроченные подсвечены, фильтры «Открытые / Просроченные / Все», статистика по 12 кодам OSF, «Скачать CSV» для Excel и Power BI. Тестовые кейсы QRG не учитываются, если не включить переключатель.

## 11. «Сервер» (по желанию)
- Вход по адресу сервера, почте и паролю, выданным администратором. Без входа приложение ничего никуда не отправляет.
- Дела на сервере — «Получить»; локальные — «Отправить» (при конфликте версий спросит, перезаписать ли). Администратор: пользователи и роли (администратор, расследователь, читатель), резервная копия и восстановление организации, журнал действий. Все: смена пароля.

## 12. «О методологии»
- Процесс, тяжесть, контрольные вопросы, категории и коды, SMARTER, QA; принципы системного мышления, Safety-II, Just Culture; PIRATe; глоссарий QRG. Источник: EUROCONTROL SOAM QRG V3 (2023), английский текст дословно.

## Если что-то пошло не так
- Данные пропали после чистки браузера — восстановите из копии: «Импорт дела из JSON» → файл `soam-backup-<дата>.json`.
- Дело не завершается — на вкладке QA в сводке готовности красным показано, чего не хватает.
- Не открывается новая версия — перезагрузите страницу; при обновлении внизу появляется сообщение.
