# Журнал решений

Одна строка на решение, с датой. Новые сверху.

- 2026-10-10 — Этап 4 начат по команде владельца («продолжи» после доклада, что бэклог без сервера исчерпан). Сервер — по желанию организации; офлайн-режим остаётся режимом по умолчанию, данные уходят только по кнопке после входа (правило CLAUDE.md о внешних запросах).
- 2026-10-10 — Сервер хранит дело целиком как пакет JSON формата экспорта (`js/bundle.js`), а не по семи таблицам: одна точка истины для проверки пакета, простая передача между браузерами, вложения внутри. Нормализация — когда понадобятся запросы по фактам (этап 4.3).
- 2026-10-10 — Конфликты: оптимистическая блокировка по версии (`baseVersion` → `409`), клиент спрашивает «перезаписать?». Слияние изменений не делаем — одно дело ведёт один расследователь.
- 2026-10-10 — БД сервера: встроенный `node:sqlite` локально и в тестах (ноль нативных зависимостей), Postgres (`pg`) на Render + Neon; SQL общий, плейсхолдеры «?» переписываются в `$n`.
- 2026-10-10 — Тесты сервера — `node --test` + `fetch` против сервера на свободном порту, без Vitest/supertest (экономия и ноль dev-зависимостей).

- 2026-10-10 — Статус дела продвигается автоматически и только вперёд по факту работы (факт → сбор, классификация → анализ, мера → меры); назад — вручную на вкладке «Событие». «Завершено» — только из QA при зелёной готовности, с любого статуса (статус доводится до «Меры» перед завершением). Причина: сквозной прогон показал, что ручная цепочка из трёх переключений блокирует кнопку «Завершить» без понятной причины.

- 2026-10-10 — Реестр мер и статистика OSF сделаны локально (по делам в браузере) без сервера: та же логика (`actionsRegistry`, `osfStats` в rules.js) переедет на сервер в этапе 4, UI не меняется.
- 2026-10-10 — Просрочка меры = срок строго раньше сегодняшней даты и статус не «выполнена»; срок «сегодня» — ещё не просрочка.
- 2026-10-10 — Глоссарий QRG хранится в таксономии как `glossary` (code = термин), показывается только на экране «О методологии»; в формах термины не подсвечиваем, чтобы не загромождать.

- 2026-10-10 — Рекомендация «расследовать или нет» (QRG, стр. 7) — подсказка, а не блокировка: АП — всегда, A/B/C — SOAM крайне желателен, E/D — по оценке затрат/пользы; «не расследовать» вопреки рекомендации помечается в форме и в отчёте, но сохраняется (решение — за организацией).
- 2026-10-10 — Доказательства в отчёте = источник факта и его вложения, выводятся под каждым фактором всех четырёх элементов (QA № 8); отдельного хранилища «доказательств» не заводим.

- 2026-10-10 — Готовность к «Завершено» дополнена: открытых вопросов по фактам 0 (QA № 4) и записан хотя бы один ключевой урок (QA № 12) — иначе эти пункты QA были галочками без данных.
- 2026-10-10 — Быстрая сортировка: подтверждение контрольного вопроса остаётся на каждую классификацию (правило 2), экономия кликов — за счёт прямых кнопок элемента и кнопки «следующий».
- 2026-10-10 — Авто-связи только двух видов: барьер → исход (всегда) и соседние уровни между фактами одного события хронологии; остальное — вручную, чтобы не рисовать связи, которых расследователь не утверждал.

- 2026-10-10 — Репозиторий `bsheraliev/soam-investigator` публичный (GitHub Pages на бесплатном плане); PDF QRG вырезан из истории (`git filter-repo`) и добавлен в `.gitignore` — лежит только локально.

- 2026-10-10 — Отчёт — печать из HTML через браузер (PDF «Сохранить как»), без библиотек; DOCX — в бэклоге.
- 2026-10-10 — Формат файла дела: `format: "soam-investigator/occurrence"`, `schema` = версия IndexedDB, вложения base64; при импорте под новым id все ссылки (факты, классификации, связи, меры, события) переписываются.

- 2026-10-10 — Интерфейс только на русском до приёмки отделом расследований; подстановка строк lang → en → ru; tj/en — подмножества ru (решение владельца).
- 2026-10-10 — План этапа показывается, подтверждения не ждём (решение владельца).
- 2026-10-10 — Схема: текст в SVG переносится вручную (`<tspan>`), без `foreignObject` — иначе PNG через canvas не собирается в части браузеров.
- 2026-10-10 — Связи на схеме рисуются через общий «ствол» между колонками (как в QRG): перекрывающиеся отрезки сливаются, 135 связей Гамильтона выглядят как на стр. 49.
- 2026-10-10 — Барьер без указанного состояния считается требующим меры (осторожная трактовка правила 4); «сработал» — мера по желанию (QRG, стр. 51).
- 2026-10-10 — Статус «Завершено» только из «Меры» и только при зелёной сводке готовности (неотсортированных 0, неподтверждённых 0, покрытие 100 %, QA 12/12).
- 2026-10-10 — Service worker: файлы оболочки берутся с `cache: 'reload'`, совпадения ищутся только в текущем кэше — иначе новая версия получает старые файлы из HTTP-кэша или старого кэша SW.

- 2026-10-10 — Вложения к фактам хранятся целиком (Blob в IndexedDB), лимит 5 МБ на файл; экспорт в JSON (этап 3) — через base64.
- 2026-10-10 — Классификация хранит `confirmed` (галочка контрольного вопроса); без неё запись не сохраняется (правило 2). В тестовых кейсах `confirmed: true` — классификацию выполнили авторы QRG.
- 2026-10-10 — Тяжесть A–E обязательна для инцидента и не требуется для АП (QRG, стр. 7: схема исключает АП).
- 2026-10-10 — Статус «Завершено» недоступен в интерфейсе до этапа 2 (правила 4 и 7); переходы статусов — только соседние.
- 2026-10-10 — Фильтра «оценочных слов» для Участия человека нет: в QRG такого списка нет, вместо него — формат и критический тест из SOAM Element Review Chart (стр. 45), добавлены в таксономию как `hi_guidance`.
- 2026-10-10 — Правка названия тестового кейса превращает `title` из объекта {en, ru} в строку — допустимо, кейс после этого считается рабочим делом.

- 2026-10-10 — Связи в кейсах: «шина» на схеме QRG (одна линия соединяет несколько блоков) развёрнута в попарные связи между соседними уровнями (OSF→CC→HI→BAR→исход); пунктир сохранён как `style: dotted`. Поэтому у Гамильтона 135 связей.
- 2026-10-10 — Состояние барьера в кейсах не проставлено (`barrierState: null`): схемы QRG не различают absent/failed.
- 2026-10-10 — «Другие системные факторы» (пунктирные блоки EE на схемах) — это OSF с флагом `otherSystem: true`, отдельного элемента SOAM нет.
- 2026-10-10 — Узел схемы = классификация (`classification`), не факт: один факт может иметь несколько классификаций, связи идут между классификациями; связь барьер→исход хранится как `toId = occurrence.id`.
- 2026-10-10 — Перевод таксономии на русский делали 4 параллельных субагента Haiku (по инструкции экономии); проверка ключей — скриптом, качество — выборочно.

- 2026-10-10 — Нумерация страниц QRG: везде используем печатный номер (внизу страницы); номер страницы в PDF-файле = печатный + 2.
- 2026-10-10 — Таксономия: английские формулировки берутся из QRG дословно (скрипт извлекает текст из PDF), русский — машинный перевод с ручной сверкой, таджикский — `tj_status: todo` до проверки владельцем.
- 2026-10-10 — Тестовые кейсы: только три опубликованные схемы из QRG (стр. 47–49); узлы и связи сняты с векторной графики PDF, текст дословно.
- 2026-10-10 — Тяжесть события: порядок A, B, C, E, D как в QRG (стр. 7), E («нет непосредственного влияния») выводится перед D («не определено»).
- 2026-10-10 — Хранилище: IndexedDB, 7 хранилищ по модели данных из CLAUDE.md, версия схемы — целое число в `js/db.js`.
- 2026-10-10 — Роутер: хеш-маршруты (`#/occurrence/<id>/facts`), чтобы работать с GitHub Pages без серверной настройки.
